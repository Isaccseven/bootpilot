A clearer view of your boot configuration.

BootPilot is a Windows desktop project for inspecting boot configuration and preparing explicit, reviewable changes.

Automated checks do not establish installation, a live Codex session or a successful hardware boot. Read the README for current validation notes.

BootPilot's documented scope

The README describes the following scope. Validation is ongoing; these descriptions do not establish successful hardware boots.

Documented scope

Understand the current setup

Inspect Windows BCD and UEFI entries, boot order and available security status. Identify Windows/Linux boot issues from system evidence, and make unavailable data explicit.

Documented scope

Review supported changes

Preview boot order, menu defaults and timeout changes. Support configuration in an existing Grub2Win installation, including validated CachyOS kernel paths.

Documented scope

Keep changes scoped

Apply current, validated plans through a narrowly scoped administrator helper, with backups, result checks and targeted recovery.

Clear limits, explicit changes

The initial scope excludes partitioning, formatting, operating system removal, firmware updates, and automatic changes to Secure Boot or BitLocker. Reboots are not automatic.

What passing tests means

Development checks use simulated adapters and temporary files. Passing those checks does not establish that a machine will boot.

One core for the desktop and Codex

The architecture pairs Tauri 2, React and TypeScript with a shared Rust core. The README describes shared operations for the desktop interface and a local MCP server for Codex.

Codex provides the assistant. BootPilot does not require its own AI API key.

Help shape the project

Explore the source, read the current development notes, or contribute a focused change. Document what you actually verified. Keep private machine inventories, credentials and recovery material out of contributions.
